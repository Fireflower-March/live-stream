## 真实直播接入（数据桥）

**一键双窗口：双击 start-all.bat** —— 自动启动打印服务 + 弹出「直播间窗口」（真实 Chrome，可在里面扫码登录抖音，登录状态记住，登录后头像抓取更全）+ 以独立应用窗口打开头像打印程序。两个窗口并排：左边看直播，右边看打印。

也可以分开启动：start.bat（打印服务）+ start-bridge.bat（数据桥，会弹出直播间窗口）。直播间地址随时在打印程序的「直播连接」面板里切换（填房间号或整条链接回车即可，数据桥会记住）。

页面自动连接 ws://127.0.0.1:8765，右上角亮起「● 直播数据 · 数据桥已连接 · 房间号」。需要 Node.js。数据桥连接期间自动演示填充会自动关闭（只打印真实观众），断开后自动恢复；无论是否连接，只要连续 30 秒没有任何观众消息（评论/点赞/礼物/关注/进场），就会自动补入测试头像避免画面空转，真实消息一到立即恢复优先。打印画面可点「弹出直播窗口」单独弹出一个 1080×1920 竖屏直播窗。

数据桥从本机浏览器的直播间页面读取弹幕：优先自己的「直播间窗口」(:9223，可登录) → BrowserOS neo(:9110) → 已开调试端口的 Chromium(:9222)。每 0.3 秒采集一次，评论/礼物/点赞秒级触发打印；礼物插队最前，评论排在点赞之前，点赞高峰期约每 0.4 秒放行一张防刷屏。关闭桥窗口即停止采集（直播间窗口可手动关掉）。

事件映射（复刻原直播间左上角规则牌）：

- 评论（含 666、999 等所有发言）→ 1 张小图（原直播间「发评论也要排队」）
- 点赞 → 按「本场点赞」增量，1 赞 1 张小图；抖音页面不公开点赞人，数据桥在累积观众花名册上交错轮换归属，**每个点赞都带真实昵称和头像**，同一人每轮最多 3 次，轮满全场再开新一轮，绝不匿名打印；轮换按活跃新鲜度优先，新观众进入花名册自动开启新一轮
- 爱心/小心心 → 1 张大图；啤酒 → 2 张大图；棒棒糖 → 3 张大图（礼物插队不打断当前打印）
- 其他礼物 → 1 张大图；进场 → 播报欢迎不打印

头像获取：观众列表/贡献条/进出场记录多来源采集并持续累积，每 8 个采集周期自动滚动带头像的面板加载更多；弹幕昵称与面板昵称按归一化（去空格和装饰 emoji）模糊匹配；仍未匹配到的观众自动点击昵称资料卡补取——每个昵称最多点 3 轮、每轮换昵称上的不同位置（靠左/居中/靠右），点开后最多等 4 秒让头像图片读取完成，每轮结束到评论区点一下关闭资料卡再换位置重试，同一昵称 6 秒后可再次尝试；就算没人发言，每 45 秒也会自动给最近活跃、还没有头像的观众补点 2 次资料卡；都拿不到时自动生成彩色首字头像，不再是灰色占位人形。评分为娱乐随机分数。页面与数据桥均只读取公开弹幕，不登录、不发弹幕、不赠送礼物。


## WebView2 桌面版
start.bat 和 start-all.bat 现在均启动独立 WebView2 应用。填写房间号，打开直播间窗口并登录，再点击开始抓取。停止抓取会停止本应用的数据桥；关闭主窗口会清理本应用启动的登录窗口和数据桥。首次使用请关闭旧版 ServerGuard、BridgeGuard 及旧数据桥，以免占用端口。新窗口使用独立登录配置，需重新登录。依赖：Python、pywebview、WebView2 Runtime 和 Node.js。
